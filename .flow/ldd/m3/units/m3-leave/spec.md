## Goal

A hero standing at any stairs landing can LEAVE the crawl without ending it.
Leaving suspends the run exactly as an app-kill does today and lands the hero
in town; the hero's own state (hit points, gear, skills, pack, gold, visit)
comes home with them. From town, the Enter Dungeon door forks while a camp
exists: **Resume** puts them back roll-for-roll — same floors, same monsters,
same streams, no reshuffle, and anything bought in town is in the pack —
or **Delve anew** abandons the camp behind a confirmation and enters fresh
(visit bumps, dungeon reshuffles, the farming loop survives). Measurable
effect: the suspend machinery built in M3S/M3H becomes reachable by play;
829 baseline tests stay green; survivability stays EXACTLY 24/40.

## Per-item contracts

### 1. `suspendRun(Profile entered, GameState state) → Profile` (core)

- Carries home from the state exactly the set of things
  `endRun(died: false)` carries (hp, equipment, skills, inventory, gold,
  visit — the code is normative, not this list), and heals nothing.
- Must NOT be called on a game-over state; the app gate is `canLeave`
  (`game_bloc.dart:132`), which already excludes it. State the contract in
  the dartdoc; how to enforce it (assert vs. nothing) is the worker's call,
  argued.
- After suspending, `profile.visit == state.visit` — the merchant shelf
  rolls forward exactly as it does after `endRun`. This invariant is what
  makes resume well-defined.
- Must not modify or discard the `GameState`; the caller keeps it.

### 2. `resumeRun(Profile profile, GameState suspended) → GameState` (core)

- For every field `suspendRun` carries home, injects the profile's CURRENT
  value back into the state (hp on the hero, equipment, skills, inventory,
  gold). Everything else — position, energy, monsters, map, explored,
  floors, depth, stairs, both rng streams, nextDropNumber, visit,
  worldSeed — is the suspended block's, untouched.
- **The identity theorem (non-negotiable, tested in content):** with no
  town activity in between, `encodeRun(resumeRun(suspendRun(p, s), s)) == encodeRun(s)` byte for
  byte. `GameState` has no `operator==`; the codec is the equality
  instrument.
- **Town flows in:** a potion bought while camped is in the resumed pack; an
  inn heal shows in the resumed hero's hp; banked gold is NOT in the
  resumed carried gold.
- Precondition: `profile.visit == suspended.visit` (see item 1). Document
  it; enforcement is the worker's argued call.
- Resuming is not entering: no visit bump, no reshuffle — extend the
  existing `loadRun` dartdoc argument to this door.

### 3. The per-hero `inside` field (content codec)

- `SavedHero` gains `inside: bool` — true only while the hero stands in
  their crawl; false in town, camped or not. REQUIRED on read (the codec
  never repairs): a hero entry without it is refused by name.
- `inside == true` with `run == null` is malformed — refused by name.
- Threads through all six document sites (`_encodeHero`/`_decodeHero, `SavedHero.broughtUpToDate, `SaveDocument.replacingActive, `one, `addingHero, `replacingActiveWithNewHero`) — the compiler will find them.
- All three golden literals regenerate BY HAND (no sed, no re.sub — the D29
  burn), in the same commit as the codec change.
- Dartdoc must carry the argument: explicit rather than derived. A derived
  discriminator exists (mid-crawl `profile.visit == run.visit - 1`; after
  suspend they are equal) and is rejected because a contract must not hang
  off an arithmetic coincidence.

### 4. TownBloc: suspended-run custody and the landmine fix

- New event `RunSuspended(GameState)`: sets profile via `suspendRun,
  holds the state as the suspended run, clears the merchant visit block
  (the visit id changed; stale buy-back ids would point at dead stock —
  dartdoc the reason).
- `TownViewState` gains the suspended run as a first-class field, distinct
  from the existing transient `run` ("the crawl to enter now"). Naming is
  the worker's (ubiquitous language: the codebase says "suspended"), but
  the two must not share a field.
- **The landmine fix:** `_settled`/`_transacted` (`town_bloc.dart:286-299`)
  carry the suspended run forward on EVERY emission, exactly as `merchant`
  is carried. Without this, the autosaver (`autosaver.dart:54`) writes
  `run: null` on the first purchase and the camp is erased from disk.
  Pinned by mutation row 3.
- Enter-dungeon fork: with no camp, `EnterDungeonPressed` behaves exactly as
  today. With a camp: Resume emits `run = resumeRun(profile, suspended)`
  and clears the suspended field; Delve-anew (its own event) clears the
  camp and calls `startDungeonRun` — `startRun` bumps the visit by
  construction, which is the reshuffle. Delve-anew is free of data loss
  (suspend already synced the hero) — say so in the dartdoc.
- `RunEnded` stays for death (`died: true`). The alive path through
  `RunEnded` becomes unreachable from the UI; whether the event keeps its
  `died` parameter is the worker's argued call. Core `endRun` keeps both
  branches — it is public API and the normative carry-set.

### 5. Screens and navigation (app)

- The stairs `Leave` control now suspends: sends `RunSuspended(state.game)`
  to the TownBloc and pops — same one-place-in-the-app shape as
  `leaveDungeon, which remains for the death overlay only. Update the
  dartdoc that says coming home "ends" the run, and revisit the `PopScope`
  rationale text if it reads stale.
- Town screen: while a camp exists, the door reads as a fork — Resume (with
  the depth visible, e.g. "Resume the crawl (depth 3)") and Delve anew
  behind a confirmation dialog (roster delete-confirm is the precedent).
  Exact layout is the worker's; both paths must be reachable and the
  abandon must never be silent.
- In-session resume needs a second entry into `_openCrawl` (today only
  `initState` resumes). `_enterDungeon`'s await-the-emission shape is the
  precedent. `resumed: true` already exists as a parameter.

### 6. Boot and autosaver

- Boot: `run != null && inside` → open the crawl (today's path, unchanged
  for app-kill mid-crawl). `run != null && !inside` → open the town with
  the camp intact and the fork available. `run == null` → town, as today.
- Autosaver: the document written must always satisfy — mid-crawl:
  `inside: true, run = the live state; camped or in town: `inside: false,
  run = the suspended run or null; the enter/leave transition may write
  either value for at most one emission. The trio through
  `replacingActive` grows to carry `inside`; how the autosaver learns it
  (town emissions vs. `watchGame`) is the worker's shape, pre-declared.
- Hazards to design against (from recon): `watchGame` is called per
  `_openCrawl` and subscriptions are only cleared wholesale at `close()` —
  repeated in-session leave/resume cycles must not stack writers or
  double-write; and the settled-skip is identity-based
  (`state.game == _run`) — a resume must hand the autosaver a state it
  will treat as changed.
