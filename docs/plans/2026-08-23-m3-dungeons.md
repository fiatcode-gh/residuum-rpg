# Implementation plan — M3D `m3-dungeons`

The sea-cave and the ruined keep, per
`docs/epic/m3-dungeons-spec-M3D.md` (local, gitignored).

Baseline measured on `bdb190b` before any change: 515 core + 300 content +
338 app = 1153 green; `survivability: 24/40 won (60.0%), stalled 0, died at
1:1 2:9 3:6 5:24`; `greedy build: 24/40 won; fleetfoot-first build: 7/40 won`.

## Shape decisions taken before code

1. **Themed spawn tables are `DungeonSpawnTable`, not `SpawnTable`.**
   `SpawnTable.rollCreature` resolves ids through `creatureById`, which
   searches the global `bestiary` list; `bestiary.dart` and
   `spawn_tables.dart` are both untouchable this unit, so a themed
   `SpawnTable` could never name a themed creature. The new type holds
   `Weighted<CreatureSpec>` directly and draws in the identical shape — one
   `rollRange(min, max)`, then one `rollRange(1, total)` — so draw-order
   parity with `buildFloor` is exact.
2. **The dungeon rides `GameBloc`, not `GameViewState`.** Every handler
   builds a fresh view state by construction; a field there would be the
   carry landmine the spec warns about, on a value that never changes inside
   one crawl.
3. **The dungeon's name reads in the hit-points row.** There is no app bar in
   `GameScreen`; that row is where `Depth N/5` already lives.
4. Node ids `sea-cave` and `ruined-keep`; glyphs `c d e h D` and `b k m C`,
   all clear of `r w g s W`, `@`, and the item glyphs `) [ !`.

## Order of work — every commit green at its exit

### 1. Characterization first (`test:`)
The crypt pin that outlives the door: `startDungeonRun`'s first floor as
ASCII plus its opening monster list at a named seed, written against the
UNMODIFIED code. Migrated to `startDungeonRunAt(cryptNode, …)` in step 3 with
the literals untouched.

### 2. The promotion (`test:`)
`wins == 24`, the depth histogram `{1: 1, 2: 9, 3: 6, 5: 24}`, and
fleetfoot `wins == 7` become assertions beside the existing band, in the
existing tests, on the existing seeds. The bot still enters by `newGame` at
visit 0.

### 3. `dungeons.dart`: the salt and the door (`feat:`)
`dungeonSalt(NodeId)` (FNV twin of `_townSalt`), `dungeonFor(node, worldSeed)`
returning `residuumDungeon(worldSeed)` for the crypt and salted builders
elsewhere, `startDungeonRunAt(NodeId, Profile)`. `startDungeonRun` deleted;
every caller migrated. Tests: crypt identity sweep, salt hygiene,
stream disjointness, the step-1 pin now green through the new door.

### 4. The save reshape (`feat:`) — one commit, goldens by hand
Hero-level required `dungeon` key, written after `run`. `SavedHero` gains the
field and refuses a run without one and a dungeon without a run.
`loadRun(from, key, {required NodeId dungeon})` builds
`dungeonFor(dungeon, worldSeed)(visit)`. Four refusal rows by name. All three
golden documents hand-edited from real encoder output in this commit.

### 5. The two dungeons (`feat:`)
`sea_cave.dart` and `ruined_keep.dart`: bestiary cast, `DungeonSpawnTable`
1..5, `DropTable` 1..5 one notch richer than the crypt's, the boss, the
trophy's forced rarity list. `themedFloor` in `dungeons.dart`: depths 1–4 are
`buildFloor`'s shape with the dungeon's tables (including its `stairsUp`
omission, preserved deliberately); depth 5 swaps the last rolled monster for
the boss and asks `generateFloor` for one extra item spawn to carry the
trophy. World gains two nodes, two routes, two rumors. Orphan test
generalized. New ASCII + spawn-list goldens per dungeon.

### 6. The app (`feat:`)
`EnterDungeonPressed(NodeId)` / `DelveAnewPressed(NodeId)`; `TownViewState`
carries `dungeon` beside `run`/`suspended` and every emission preserves it;
world-screen doors per ruling 4 including the abandon-elsewhere
confirmation; autosaver and boot carry the field; dungeon name in the crawl;
per-theme palette on `GlyphGrid`.

### 7. The bands (`test:`)
Mid-progression fixture kit, `startDungeonRunAt` entry, band 0.50–0.95 and
`stalled == 0` per dungeon, exact figures printed and pinned. Any table tune
is reported with its re-measurement.

### 8. Verification
Three suites, `flutter analyze`, `dart format`, the full mutation table on
committed code, diff scope, hygiene greps, AVD pass on `Pixel_10`.
